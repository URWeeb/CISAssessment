## Гайд по компиляции и использованию написанного решения

### Требования
 
- CMake версии $\ge 3.14$
- GNU Make версии $\ge 3.81$
- Компилятор с поддержкой C++20
- Установленный дистрибутив Linux или MacOS

### Сборка
 
```bash
make build
```
 
После сборки в `build/` появляются `publisher_server`, `publisher_client`, `publisher_tests`.
 
### Тесты
 
```bash
make test
```
 
Есть возможность запустить стресс-тесты с `-O3`:
 
```bash
make stress-test
```
 
### Запуск сервера
 
```bash
make run-server
```
 
Параметры сервера:
 
| Флаг                     | По умолчанию | Смысл                                              |
|---------------------------|---------------|----------------------------------------------------|
| `--port=`                 | 7878          | TCP-порт                                           |
| `--roster=`                | —             | CSV с клиентами (`id,name,level,trust,is_editor`)  |
| `--threshold=`             | 0.75          | Порог суммарного доверия для публикации сюжета     |
| `--half-life-hours=`       | 6             | Период полураспада доверия во времени              |
| `--congratulate-top=`      | 3             | Сколько первых причастных получают поздравление    |
 
### Запуск клиента
 
```bash
./build/publisher_client <host> <port> hello <client_id>
./build/publisher_client <host> <port> note  <client_id> <idempotency_key> <категория> <тема...>
./build/publisher_client <host> <port> stats <client_id>
./build/publisher_client <host> <port> stats-all <client_id>
./build/publisher_client <host> <port> poll  <client_id> <since_seq>
```
 
Пример:
 
```bash
./build/publisher_client 127.0.0.1 7878 hello krislok
./build/publisher_client 127.0.0.1 7878 note krislok k1 техника nvidia не будет выпускать новые потребительские видеокарты
./build/publisher_client 127.0.0.1 7878 stats krislok
```


## Какие решения были приняты в ходе решения этой задачи

- **Протокол** - текстовый, по TCP, поля разделены табуляцией, одна команда - одна строка.
- **Concurrency** - один `std::thread` на подключение, без пула
  потоков, поскольку соединения короткие (одна команда - один ответ), пул добавил бы сложности без заметной выгоды на ожидаемой нагрузке.
- **Потокобезопасность `Store`** - единый `std::mutex` на все операции с сюжетами/клиентами.
  Проверка порога публикации и сама публикация происходят под одной и той же блокировкой
  (`SubmitContribution`), поэтому при гонке нескольких клиентов по одному сюжету ровно один вызов
  получит `published_now == true` - это и проверяется тестом с 50 потоками.
  `Mailbox::Box` - отдельный `std::mutex` на ящик, чтобы запись в почту одного клиента не ждала
  блокировку `Store`.
- **Идемпотентность** - реализовывалась по паре (`client_id`, `idempotency_key`), а не по содержимому заметки. Тогда повторная отправка той же команды  не создаёт второй вклад и возвращает тот же `Receipt`, что и в первый раз.
- **Порог публикации** - суммарное доверие причастных клиентов, а не их количество: один высокодоверенный источник может опубликовать сюжет сразу, несколько низкодоверенных - только в сумме.
- **Распад доверия во времени** - выбрана экспоненциальная модель $\text{weight} \cdot 2^{-\frac{\text{elapsed}}{\text{half-life}}}$.
- **Доступ к сводной статистике** - только у `is_editor`. Проверка прав стоит прямо в `Service::AllStats` (если не редактор - бросаем `ServiceError{FORBIDDEN}`), а не в коде протокола, чтобы правило было в одном месте и его можно было протестировать юнит-тестом напрямую, без поднятия сервера и сокетов.
